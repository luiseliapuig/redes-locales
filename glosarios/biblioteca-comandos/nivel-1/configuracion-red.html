Nivel 1 · Etapa 2 — Descubrir la terminal

Mi ordenador en la red

Aprenderás a consultar las interfaces de red de tu ordenador, identificar sus direcciones IP y MAC, localizar la puerta de enlace, consultar los DNS y configurar los parámetros básicos de red.

Ejecuta los comandos en la terminal de Linux o en el Símbolo del sistema de Windows. Las salidas dependen del equipo y de su conexión. Para modificar la configuración necesitarás permisos de administrador y conocer el nombre real de tu interfaz o conexión. Practica preferentemente en una máquina virtual: algunos cambios pueden cortar la conexión.

A. Direcciones e interfaces

LinuxWindows CMD

Consultar las direcciones IP Consultar

LinuxMuestra interfaces y direcciones IP
Windows CMDMuestra direcciones y configuración básicaMuestra la configuración detallada

Muestra las direcciones asignadas a las interfaces. Una interfaz puede tener direcciones IPv4 e IPv6.

Fíjate en: en Linux, inet 192.168.1.25/24 es IPv4 y inet6 señala IPv6; el número tras / es el prefijo. En CMD, busca «Dirección IPv4», «Dirección IPv6» y «Máscara de subred», por ejemplo 255.255.255.0.

Diferencias: ipconfig /all añade datos como servidores DNS y DHCP e información del adaptador; no es una salida idéntica a ip addr.

Identificar las interfaces de red Consultar

LinuxMuestra las interfaces y su estado
Windows CMDMuestra las interfaces y su estado

Una interfaz es el punto mediante el que el equipo se conecta a una red. Puede corresponder a un dispositivo físico, como Ethernet o Wi-Fi, o ser virtual.

Fíjate en: el nombre y el estado de cada interfaz: por ejemplo, enp0s3 y state UP en Linux, o «Ethernet» y su estado en CMD. El estado no garantiza por sí solo que haya acceso a Internet.

Diferencias: Linux muestra indicadores de enlace; CMD distingue el estado administrativo del estado de conexión.

B. Enlace y rutas

LinuxWindows CMD

Consultar la dirección MAC Consultar

LinuxMuestra las direcciones de enlace
Windows CMDMuestra las direcciones MACAñade los nombres de conexión y adaptador

Consulta la dirección de enlace asociada a cada interfaz. Una MAC suele representarse con seis pares hexadecimales, por ejemplo 02:11:22:33:44:55.

Fíjate en: en Linux, la línea link/ether bajo el nombre de la interfaz; en CMD, «Dirección física» y, con /v, el nombre de conexión para relacionarla con el adaptador.

Importante: la dirección MAC suele venir asignada de fábrica a la interfaz de red y normalmente es fija. En determinadas situaciones, el sistema operativo puede utilizar temporalmente una MAC diferente.

Identificar la puerta de enlace Consultar

LinuxMuestra las rutas IPv4, incluida la predeterminada
Windows CMDMuestra la puerta de enlace de cada adaptador

La puerta de enlace es normalmente el dispositivo al que se envía el tráfico destinado a otras redes.

Fíjate en: en Linux, una línea como default via 192.168.1.1 dev enp0s3; la dirección tras via es la puerta de enlace. En CMD, busca «Puerta de enlace predeterminada» en el adaptador usado.

Diferencias: ip route muestra rutas IPv4; ipconfig presenta la información agrupada por adaptador.

Consultar la tabla de rutas Consultar

LinuxMuestra las rutas IPv4
Windows CMDMuestra las tablas de rutas IPv4 e IPv6

La tabla de rutas indica por dónde puede enviar el equipo los paquetes hacia distintas redes. Un equipo puede conocer varias rutas.

Fíjate en: la ruta por defecto: default en Linux y, en la tabla IPv4 de CMD, el destino 0.0.0.0 con máscara 0.0.0.0. Observa también las rutas de redes conectadas.

Diferencias: ip route muestra por defecto rutas IPv4; route print presenta tablas IPv4 e IPv6.

C. Servidores DNS

LinuxWindows CMD

Consultar los servidores DNS Consultar

LinuxMuestra la configuración DNS de systemd-resolved
Windows CMDMuestra la configuración detallada, incluidos los DNS

Los servidores DNS ayudan a traducir nombres como ejemplo.com a direcciones IP.

Fíjate en: «DNS Servers» en la información global o de cada interfaz de Linux y «Servidores DNS» en el adaptador de CMD. Puede aparecer más de una dirección.

Diferencias: resolvectl no está disponible en todas las distribuciones; depende de systemd-resolved. ipconfig /all incluye además otros datos del adaptador.

D. Configuración estática

LinuxWindows CMD

enp0s3 y Ethernet son nombres de interfaz de ejemplo; Conexión cableada 1 es un nombre de perfil. Adáptalos a tu equipo. En Linux, los comandos temporales cambian el sistema en ejecución; los permanentes guardan los datos en un perfil de NetworkManager. Son alternativas, no pasos obligatorios de una misma operación. Necesitas permisos de administrador. Cambiar la configuración puede interrumpir la conexión; practica preferentemente en una máquina virtual.

Asignar una dirección IPv4 estática Configurar

LinuxTemporalAñade temporalmente una dirección IPv4PermanenteGuarda una dirección IPv4 estática en el perfil de conexión
Windows CMDEstablece IP, máscara y puerta de enlace

Usa una dirección adecuada para la red que no esté asignada a otro equipo.

Fíjate en: /24 equivale a 255.255.255.0. En Linux se añade la dirección y pueden permanecer otras anteriores; en Windows se sustituye la configuración IPv4 estática.

Configurar la puerta de enlace Configurar

LinuxTemporalCambia temporalmente la ruta predeterminadaPermanenteGuarda la puerta de enlace en el perfil de conexión
Windows CMDLa puerta de enlace está incluida en el comando de IPv4 anterior.

La puerta de enlace permite enviar tráfico hacia otras redes. Debe ser alcanzable desde la interfaz configurada.

Importante: cambiarla puede cortar la conexión. Comprueba el resultado con ip route o ipconfig.

Configurar servidores DNS Configurar

LinuxTemporalAsigna temporalmente un servidor DNS a la interfazPermanenteGuarda un servidor DNS manual en el perfil de conexión
Windows CMDEstablece un servidor DNS manual

El servidor DNS ayuda a traducir nombres a direcciones IP. En Linux, el comando requiere systemd-resolved y su configuración puede cambiar al reconectar.

Fíjate en: verifica los servidores con resolvectl status o ipconfig /all; consulta la etapa 4 para comprobar la resolución.

Aplicar los cambios guardados

Linux Reactiva la conexión para aplicar los cambios guardados

Los comandos nmcli con mod guardan los parámetros en el perfil. Para aplicarlos, activa de nuevo la conexión. Esto puede interrumpir temporalmente la red.

E. DHCP y mantenimiento

LinuxWindows CMD

Volver a obtener IPv4 automáticamente Configurar

LinuxActiva IPv4 automática en el perfil
Windows CMDActiva la obtención automática de IPv4

DHCP permite recibir una dirección IPv4 automáticamente. En Linux se necesita NetworkManager: sustituye Conexión cableada 1 por el nombre del perfil y reactívalo como se indica en «Renovar una concesión DHCP».

Importante: el comando de Linux no elimina necesariamente direcciones o ajustes manuales previos del perfil. En ambos sistemas, activar DHCP para IPv4 no garantiza que los DNS manuales vuelvan a ser automáticos; comprueba la configuración por separado.

Activar o desactivar una interfaz Configurar

LinuxActiva la interfazDesactiva temporalmente la interfaz
Windows CMDActiva la interfazDesactiva la interfaz

Permite cambiar el estado administrativo de una interfaz, sin modificar por sí solo la IP configurada.

Importante: al desactivar la interfaz perderás la conexión por ella. Haz la prueba en un equipo o máquina virtual donde puedas recuperarla localmente.

Renovar una concesión DHCP Configurar

LinuxDesconecta el perfil de NetworkManagerReconecta y solicita configuración automática si usa DHCP
Windows CMDLibera la concesión IPv4 del adaptadorSolicita una nueva concesión IPv4

Permite solicitar de nuevo parámetros automáticos cuando el perfil o adaptador utiliza DHCP.

Diferencias: desconectar y reconectar un perfil con nmcli no es exactamente lo mismo que liberar y renovar una concesión con ipconfig. Ambas operaciones pueden cortar la conexión; el nombre que acepta ipconfig debe coincidir con el adaptador.

Vaciar la caché de resolución DNS Diagnosticar

LinuxVacía la caché de systemd-resolved, si está instalado
Windows CMDVacía la caché del cliente DNS de Windows

Elimina respuestas DNS guardadas localmente para que las próximas consultas puedan obtener información actualizada.

Importante: no cambia los servidores DNS configurados ni garantiza que se resuelva un problema de conectividad. En Linux depende del servicio de resolución utilizado.
