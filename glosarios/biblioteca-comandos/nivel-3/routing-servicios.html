Nivel 3 · Etapa 6 — Administrar redes

Routing y servicios

Aprenderás a configurar interfaces y routing entre VLAN, consultar rutas y preparar servicios DHCP y NAT/PAT en un router Cisco IOS.

Escenario de laboratorio aislado: VLAN 10 ALUMNOS (192.168.10.0/24, puerta de enlace 192.168.10.254) y VLAN 20 PROFESORES (192.168.20.0/24, puerta de enlace 192.168.20.254), mediante subinterfaces de g0/0. La salida utiliza g0/1. Los nombres de interfaces y funciones dependen del modelo y la versión. Los ejemplos modifican la configuración y pueden interrumpir conexiones: úsalos solo en equipos de prácticas preparados para ello.

¿Ya conoces los comandos? Consulta el glosario rápido Cisco IOS. Los indicadores de terminal muestran el modo y no se escriben; el acceso privilegiado puede pedir contraseña.

A. Interfaces y direccionamiento IP

Cisco IOSRouter

Configurar una interfaz del router Configurar

Configuración globalSelecciona la interfaz físicaConfiguración de interfazAsigna IPv4 y máscara a la interfazHabilita administrativamente la interfaz

Ejemplo independiente para una red directamente conectada 192.168.1.0/24. Al seleccionar la interfaz aparece Router(config-if)#.

Importante: no combines esta IP en g0/0 con el montaje de subinterfaces siguiente; en aquel escenario la interfaz física no lleva dirección IP.

Secuencia completa · red directa independienteRouter> enable
Router# configure terminal
Router(config)# interface g0/0
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config-if)# no shutdown
Router(config-if)# end
Router# show ip interface brief

Consultar el estado de las interfaces Consultar

Fíjate en: Status refleja el estado físico o administrativo y Protocol el protocolo de línea. Una interfaz administrativamente habilitada puede seguir caída por falta de enlace u otros problemas.

B. Routing entre VLAN

Cisco IOSRouter

Configurar subinterfaces para varias VLAN Configurar

Configuración globalCrea o selecciona la subinterfaz para la VLAN 10Configuración de subinterfazAsocia la subinterfaz a la VLAN 10Define la puerta de enlace de la VLAN 10

En router-on-a-stick, el switch debe tener las VLAN 10 y 20 y un puerto trunk operativo hacia g0/0, que permita ambas VLAN. La interfaz física se habilita y las direcciones se asignan a las subinterfaces. Si se usó el ejemplo independiente anterior, retira antes la IP de g0/0.

Fíjate en: IOS utiliza habitualmente Router(config-subif)# para las subinterfaces; el indicador y los nombres pueden variar según la plataforma.

Secuencia completa · trunk y VLAN ya preparados en el switchRouter> enable
Router# configure terminal
Router(config)# interface g0/0
Router(config-if)# no ip address
Router(config-if)# no shutdown
Router(config-if)# exit
Router(config)# interface g0/0.10
Router(config-subif)# encapsulation dot1Q 10
Router(config-subif)# ip address 192.168.10.254 255.255.255.0
Router(config-subif)# exit
Router(config)# interface g0/0.20
Router(config-subif)# encapsulation dot1Q 20
Router(config-subif)# ip address 192.168.20.254 255.255.255.0
Router(config-subif)# end
Router# show ip interface brief
Router# show ip route connected

Fíjate en: C identifica redes conectadas, L direcciones locales de interfaces y S rutas estáticas, cuando aparecen. Las rutas instaladas dependen del estado y la configuración.

Configurar una ruta estática Configurar

Configuración globalEnvía el tráfico hacia esa red al siguiente salto

En este ejemplo, otro router conectado a VLAN 20 tiene la IP 192.168.20.1 y acceso a 192.168.30.0/24. La subinterfaz g0/0.20 debe estar operativa para alcanzar ese siguiente salto. El router vecino también necesita rutas de retorno.

Secuencia completa · VLAN 20 y vecino ya operativosRouter> enable
Router# configure terminal
Router(config)# ip route 192.168.30.0 255.255.255.0 192.168.20.1
Router(config)# end
Router# show ip route

D. DHCP — Asignación automática

Cisco IOSRouter

Reservar direcciones fuera del reparto Configurar

Configuración globalExcluye la puerta de enlace del reparto DHCP

Evita que el servidor entregue esa dirección a un cliente. Excluye también otras direcciones estáticas que existan en la red antes de activar el reparto.

Crear un pool DHCP Configurar

Configuración globalCrea o selecciona el pool y abre su configuraciónConfiguración DHCPDefine la red de direcciones del poolIndica la puerta de enlace para los clientesIndica el servidor DNS para los clientes

La exclusión y la selección del pool se hacen en configuración global; sus parámetros se introducen en Router(dhcp-config)#. El DNS del ejemplo debe ser accesible desde los clientes.

Secuencia completa · VLAN 10 operativa y sin otro DHCP conflictivoRouter> enable
Router# configure terminal
Router(config)# ip dhcp excluded-address 192.168.10.254
Router(config)# ip dhcp pool ALUMNOS
Router(dhcp-config)# network 192.168.10.0 255.255.255.0
Router(dhcp-config)# default-router 192.168.10.254
Router(dhcp-config)# dns-server 8.8.8.8
Router(dhcp-config)# end
Router# show ip dhcp pool
Router# show ip dhcp binding

Consultar las asignaciones DHCP Consultar

EXEC privilegiado · Router#Muestra las concesiones de direccionesMuestra los pools y su utilización

Fíjate en: las direcciones concedidas y los identificadores de cliente; el pool muestra la red y el número de direcciones asignadas. Puede no haber concesiones hasta que un cliente solicite una dirección.

E. NAT/PAT — Salida a otras redes

Cisco IOSRouter

Ejemplo de laboratorio: VLAN 10 en g0/0.10; red exterior 203.0.113.0/30, con g0/1 en 203.0.113.2 y router vecino en 203.0.113.1. Estas direcciones son de documentación, no una asignación pública para uso real.

Identificar interfaces internas y externas Configurar

Configuración de interfazMarca la interfaz o subinterfaz internaMarca la interfaz exterior

Aplica inside en g0/0.10 y outside en g0/1, cada uno desde el modo de configuración correspondiente. La secuencia completa aparece en la siguiente función.

Configurar PAT Configurar

Configuración globalSelecciona la red interna que se traduciráComparte la dirección de salida mediante PAT

La lista 1 identifica la VLAN 10; g0/1 proporciona la dirección traducida. overload permite que varios equipos compartan esa IPv4 distinguiendo comunicaciones mediante puertos.

Importante: el ejemplo presupone que la lista 1 está libre y no existen reglas NAT o rutas predeterminadas incompatibles. PAT no sustituye a las rutas. El vecino 203.0.113.1 debe estar operativo y alcanzar las redes de destino; los clientes deben usar su puerta de enlace. Para acceso real se necesita una dirección y conectividad proporcionadas por la red exterior.

Secuencia completa · subinterfaz VLAN 10 ya configurada y enlace exterior conectadoRouter> enable
Router# configure terminal
Router(config)# interface g0/0.10
Router(config-subif)# ip nat inside
Router(config-subif)# exit
Router(config)# interface g0/1
Router(config-if)# ip address 203.0.113.2 255.255.255.252
Router(config-if)# ip nat outside
Router(config-if)# no shutdown
Router(config-if)# exit
Router(config)# access-list 1 permit 192.168.10.0 0.0.0.255
Router(config)# ip nat inside source list 1 interface g0/1 overload
Router(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
Router(config)# end
Router# show ip interface brief
Router# show ip route
Router# show ip nat translations

Consultar las traducciones NAT Consultar

EXEC privilegiado · Router#Muestra las traducciones NAT activas

Fíjate en: Inside local identifica la dirección interna original y Inside global su dirección traducida; Outside local y Outside global describen el extremo exterior. En PAT también aparecen puertos.

La tabla puede estar vacía hasta que exista tráfico que cumpla la regla.
